# 评审记录 · 第 1 轮（用户视角）

> 评审人：把自己当作这个产品的典型用户（Windows 用户，家里 + 公司 + 常去的店都连过 WiFi，偶尔要给来客/新手机找密码）。
> 评审对象：`prototype/ui-prototype.html` v1（三个变体：A 卡片网格 / B 主从分栏 / C 控制台表格）。

## 一、我（用户）是怎么用这个工具的

1. **最常见的动作**：打开 → 扫一眼找到那个 WiFi → 复制密码发给别人 / 填到新设备。
2. 找的通常是**当前连着的**或**刚连过的**那个网络。
3. 偶尔需要把密码**给手机扫码**（来客、新手机没有键盘/难输入）。
4. 身边有人时不想让密码大喇喇晾在屏幕上。

结论：**发现要快、复制要快、屏上要可控**。界面的核心 KPI 不是"好看"，是"三秒内拿到密码"。

## 二、变体结论

- **B（主从分栏）胜出**：左侧列表信息密度高，右侧"密码大字 + 大按钮复制"，一次点击直达，最贴近核心动作。
- A（卡片网格）：好看、亲和，但一屏只能放 9 张卡，网络多了要滚，查找效率低。适合"展示"不适合"找东西"。
- C（控制台表格）：密度和键盘效率最好，但一眼"程序员工具"，普通用户会发怵；它的**键盘流**值得搬到 B 里。
- **迭代方向 = B 的骨架 + A 的亲和细节 + C 的键盘效率。**

## 三、改进建议（按优先级）

### P0 · 原型阶段就要修

| # | 问题 | 建议 |
|---|------|------|
| 1 | 当前连接的网络没有置顶，也没有明显高亮 | **已连接网络置顶 + 高亮**；打开时默认选中它 |
| 2 | 想"一眼看全"时需要逐张点眼睛 | 全局**一键全部显示 / 全部隐藏**；并支持 **Esc 一键全部隐藏**（防投屏/截图泄漏） |
| 3 | 复制成功的提示里带着密码明文（`已复制到剪贴板：HomeSweet#2024`） | 提示只留「密码已复制」，**不要在屏幕上二次暴露密码** |
| 4 | 没有二维码——给手机连 WiFi 的场景缺失 | 密码面板加**二维码弹窗**（原型先用示意图，正式版生成可扫的真二维码） |
| 5 | A 的「全部显示」按钮点了之后文字不变（小 bug） | 按钮文案随状态切换：全部显示 ↔ 全部隐藏 |

### P1 · 正式实现时必须有

- **键盘流**（吸收 C 的优点）：`/` 聚焦搜索；`↑↓` 选择网络；`Enter` 显示/隐藏；`C` 复制。
- **搜索空状态**：搜不到时要给明确提示和"清除搜索"入口（现在 A 有、B/C 弱）。
- **无密码网络的说明**：开放网络 / 802.1X 企业网络要区分展示原因，禁用按钮要有说明（原型已示意，实现时保留）。
- **首次打开的安全说明**：一句话说明"密码读取自本机存档，工具不联网、不上传"，后续不再打扰。

### P2 · 锦上添花

- 导出全部密码（CSV/TXT），方便换机迁移备份。
- 排序切换（名称 / 状态）。
- 深色主题跟随系统。
- 托盘图标 / 开始菜单快捷方式。

## 四、给"实现阶段"的硬要求（从评审提炼）

1. 结构选 **B**；已连接置顶、默认选中。
2. 全局显示/隐藏控制（含 Esc），复制提示不出现明文。
3. 二维码功能要在正式版可用（可扫）。
4. 键盘操作闭环：`/`、`↑↓`、`Enter`、`C`、`Esc`。
5. 复制前不需要用户先"显示"密码（直接复制是允许的），但屏幕上默认保持遮罩。
